2 m Interactive AO Experiment

A precomputed native 2 m Shack-Hartmann SCAO loop with a synthetic on-axis guide source: one seed, 180 frames at 1 kHz, burn-in 40. Your browser replays recorded frames and selects recorded cases; it does not simulate, interpolate or draw noise.

Generate an experiment

  
Run the same native 2 m Shack-Hartmann SCAO model on a turbulence realization of your choice, with a bounded set of parameters, and replay its time evolution. A connected computation service runs the real AO simulation; each run is computed in full first and then played back, so computation does not keep pace with the 1 kHz loop. The precomputed experiment above and the Research Results never need the service.

      Methods & Limits
      
  
      
    
      Model families on this site
      
    
        
      
      • Native time-domain SCAO (the 2 m experiment, R1–R5 and the ESO-tier convergence studies of R8): a frame-by-frame closed loop with a Shack-Hartmann sensor, a deformable mirror, a TSVD or sparse reconstructor and a leaky-integrator controller with queued delay. Detector-level profiles add a physical camera (photon, read and sky noise, calibration products).
        • 
      
      • HCIPy time-domain components (R7): an independent backend compared with the native one on an accepted small fixture.
        • 
      
      • Analytical MCAO adapter (R6 and the analytical-study checks of R8): P3 sampled correction-band PSD plus a continuous fitting-tail completion propagated by MASTSEL. It is a separate study, not an extension of the native loop.
        • 
    
      
    
      Wavelengths, residual conventions, noise settings, profiles, sampling windows and budgets differ between these families and between studies; the site never merges them into one performance comparison.
      

    
      The 2 m experiment
      
    
        

    
        Generated experiments
        
    
          
      
        • What runs: the same canonical native closed loop, observer and science propagator as the precomputed experiment, on profile det_emccd_2m_synthetic@1. A visitor may change only the realization seed, r0 (at 500 nm), wind speed and direction, the guide-source AB magnitude, the controller gain, the queued delay, the frame count, the burn-in and the replay stride, within ranges the service publishes and validates; aperture, WFS/DM sampling, atmosphere model and wavelengths are fixed.
          • 
      
        • Randomness and time: a run generates one seeded realization at t = 0 and evolves it by frozen flow; frames are never redrawn. A new realization has a new seed and identity. Before computing, every atmosphere request time is checked against the finite screen's support; a request beyond it is refused, never wrapped, reset or slowed. A finite run ends normally; looping a replay is labelled as replay.
          • 
      
        • Comparisons: changing gain, guide magnitude or delay keeps the atmosphere of the same seed; a comparison is labelled paired only when the time grids and every per-frame atmosphere digest match. Changing r0 or wind changes the physical atmosphere; a new seed is a new realization. Calibration is rebuilt for every run and its identity follows the seed and guide magnitude.
          • 
      
        • Images: instantaneous PSFs of each frame's atmosphere (zero DM) and pre-update residual; synthetic observations convolve the fixed binary with those numerical PSFs; running and completed-window averages use every eligible frame, independently of how many frames are kept for replay.
          • 
      
        • Computation: the service runs one job at a time in its own worker process with two native threads and a time limit; cancelling stops that process. A run is computed in full before it is replayed; it does not keep pace with the 1 kHz loop. Generated runs have their own identities and storage and never change the precomputed dataset.
          • 
      
        • Running a service: from a checkout with the package installed, python scripts/ao_dynamic/service.py --port 8765 --web-dir web serves this site and the API at http://127.0.0.1:8765/ao-explorer/?backend=/. A service on another origin must list this page's origin with --allow-origin; an HTTPS page needs an HTTPS service. This published site has no service of its own.
          • 
    
        

    
        Observable definitions
        
    
          
      
        • Residual RMS: pupil RMS of the pre-update residual (what the WFS measured) after removing the pupil mean, in nm OPD. Mean per-frame RMS and the root of the mean square are reported separately.
          • 
      
        • Peak Strehl: peak angular surface brightness of an image over that of the zero-OPD image of the same propagator and grid. The mean of instantaneous Strehl and the Strehl of the averaged image are different quantities and are labelled as such.
          • 
      
        • Averaged image: the equal-weight mean of 140 sampled instantaneous intensities (frames 40–179). The averaged OPD is never propagated; tilt is kept and nothing is recentred.
          • 
      
        • Validity: measured fractions of valid measurement rows and sub-apertures, and whether the reconstructor returned an estimate. No lock classifier is claimed.

              Local preview
              
    
              The site is static and needs an HTTP server; opening index.html from the file system is not supported. From the repository root run python3 -m http.server 8000 --directory web and open http://localhost:8000/ao-explorer/. All assets are bundled; the page makes no external requests. Source links in the Research Results open the repository at the recorded commit on GitHub, an external site, only when followed.
              
    
              The page's code lives in a directory named after its content (code-<build>/) and the dataset entry records that build, so a browser cannot combine a cached older script with newer data: a page whose code does not match the entry says so and asks for a reload.
